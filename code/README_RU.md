# Лисёнок — обновлённый проект

Проект собран из загруженных файлов. Основная точка входа — **Main.py**.
Проверенная версия Python — **3.11.17**. Python 3.12/3.13 для этих зависимостей не используйте.

## Запуск

1. Остановите старый экземпляр бота. Сохраните резервную копию его папки.
2. Распакуйте проект в отдельную папку. В архиве есть загруженные вами `DataBase.sql` и `ads.sqlite3`, без изменения их содержимого. Если рабочая база уже обновлялась после загрузки в чат, используйте именно более свежую рабочую базу, а не копию из архива. Не заменяйте работающую базу, пока бот запущен.
3. Оставьте `admin.env` рядом с кодом. Его содержимое и остальные загруженные файлы с ключами сохранены без изменений.
4. Установите зависимости и запустите:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.lock
python manage.py check
python Main.py
```

В Windows используйте `py -3.11 -m venv .venv` и `.venv\Scripts\activate`.
Также поддерживается `python -m pip install -r requirements.txt`; lock-файл фиксирует и транзитивные зависимости.
Запускайте только **один** экземпляр polling на один токен.

## Настройки

Приоритет: переменные процесса, затем `.env`, затем `admin.env`, затем `.env.env`. Уже заданные значения не перезаписываются. Для токена используется `BOT_TOKEN`, а при его отсутствии — `API_TOKEN`. Значения ключей не удалены и не заменены; тесты используют собственный синтетический токен.

Администраторы читаются из `ADMIN_IDS` (через запятую), основной администратор — из `ADMIN_ID`, либо первый из `ADMIN_IDS`. Настройки `FARMANDER_ID`, `BOBR_IDS`, `MY_CUSTOM_NAME`, `MAIN_CHAT_ID`, `BLOCKED_BOT_IDS`, `LOG_FILENAME` также читаются из ваших env-файлов.

Необязательные параметры можно добавить в `.env`:

```dotenv
INACTIVE_USER_DAYS=180
AD_INTERVAL_HOURS=24
# Для отдельных путей используйте абсолютные имена:
# BOT_DB_PATH=/path/to/DataBase.sql
# ADS_DB_PATH=/path/to/ads.sqlite3
```

Пути к данным и переводам по умолчанию считаются относительно папки проекта, а не текущего каталога терминала.

## База данных и очистка

- До первой миграции старой схемы создаётся SQLite backup в `db_backups` рядом с основной базой. Миграция добавляет недостающие поля и индексы, восстанавливает допустимые старые связи с чатами, сохраняет профили и игровые данные.
- Некорректный старый `chat_id` очищается, не удаляя игрока. Его исходное значение остаётся в резервной копии. При следующем сообщении связь создаётся заново.
- Сообщения любого типа обновляют имя и активность пользователя; повторная регистрация сохраняет никнейм, зубы и длину хвоста. Один игрок может состоять в нескольких чатах.
- Выход из группы удаляет только связь с этой группой. Удаление бота из группы сохраняет профили игроков и их другие связи. Временная ошибка Telegram не вызывает удаления данных.
- Автоматическая очистка запускается ежедневно в **03:10 Europe/Kyiv**. Удаляются профили с последней активностью строго раньше `INACTIVE_USER_DAYS` дней и их связи. Перед удалением создаётся backup. Если в старой записи неизвестны и активность, и рост хвоста, при миграции даётся новый срок ожидания. Если в старой базе есть достоверная старая дата, она учитывается при очистке.
- Для групповых сообщений Telegram должен передавать обновления боту: при необходимости настройте privacy mode через BotFather. Бот не может учитывать сообщения, которые Telegram ему не отправил. Получение `chat_member` требует прав администратора группы; уходы также обрабатываются по служебным сообщениям.
- Лимит роста — один час, предсказания обновляются по календарному дню Киева, лимит потери хвоста от укусов — 20 см за день UTC. Дата укуса хранится отдельно от даты роста и не сбрасывает часовой таймер.
- Логи ротируются ежедневно, хранятся семь архивов. Ключи скрываются в выводе, включая traceback.

Ручное обслуживание (используйте те же env-файлы и путь к базе, что у бота):

```bash
python manage.py check
python manage.py backup
python manage.py cleanup --days 180 --dry-run
python manage.py cleanup --days 180
```

Последняя команда действительно удаляет неактивные профили. На загруженной исходной базе во время подготовки проекта очистка не запускалась.

## Собственная реклама

Команды доступны администраторам из `ADMIN_IDS`/`ADMIN_ID`:

```text
/ads_help
/ad_add Название | Текст объявления | https://example.com
/ad_edit ID | Новое название | Новый текст | https://example.com
/ad_list
/ad_test ID
/ad_on ID
/ad_off ID
/ad_delete ID
/ad_stats
/ad_stats ID
/ads_pause
/ads_resume
```

- URL необязателен; в `/ad_edit` пустой URL убирает кнопку.
- `/ad_test` показывает предпросмотр в личном чате администратора без изменения статистики и суточного лимита.
- Обычные показы идут только в личных чатах после входящего сообщения, не чаще одного раза за заданный интервал на пользователя. Фоновой массовой рассылки рекламы нет.
- Команды управления рекламой и незавершённый FSM-диалог не вызывают рекламного показа.
- Статистика показов и суточный лимит обновляются после успешного ответа Telegram на отправку. Ошибка отправки не засчитывается как показ.
- Бронь показа защищает от одновременных сообщений; незавершённая бронь истекает через пять минут. В случае аварии процесса между отправкой Telegram и записью в SQLite абсолютная гарантия ровно одного показа невозможна.
- Клик считается один раз на доставленное объявление и пользователя. Считается нажатие «Подробнее», а не подтверждённое посещение внешнего сайта.
- При удалении кампании исторический суточный лимит пользователя сохраняется.
- Длинные списки статистики разбиваются на сообщения. Размер объявления проверяется до сохранения.

Собственные объявления не создают автоматических выплат Telegram. `/telegram_ads_info` содержит справку об официальной монетизации; её доступность определяется Telegram.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты используют временные базы и синтетический токен, Telegram-вызовы подменены. Проверяются миграция копии загруженной базы, сохранение данных, активность, многократная регистрация, связи с чатами, очистка/backup, лимиты, укусы, предсказания, маршрутизация команд, доставка рекламы и клики.

Реальное подключение по вашему токену и работа внешних сервисов изображений в этой среде не подтверждены. Они зависят от действительности ключей, доступности API, сети и разрешений Telegram. Перед заменой рабочего экземпляра проверьте `/start`, `/help`, `/tail`, `/predict`, `/prof`, `/ads_help` и `/ad_test ID` в своём тестовом чате.
